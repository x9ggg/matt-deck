# Pane 布局

Claude Code 一侧 Pane 的等宽线框图，是各个视图实现的依据（#3）。Pane 用 Mods 的元素画在字符格子里（ADR-0002），所以这里画的就是字符。Codex 的界面不在这里。

图里的 Task、Session 和时间都是示例数据。画面在 2026-11-12 按真实 Pane 里的验证结果改过一遍，结果和还没验证的部分在最后一节。

## 怎么读这些图

- 每张图是 Pane 正文区里的字符。引擎自己画的不在图里：停靠时是左边一条竖线和顶上放关闭标记的一行；在输入框上方时是一圈圆角边框，左右各留 1 列。
- 停靠在侧边的图按 42 列画，输入框上方的按 96 列画。实际列数读 `Pane` 的 `bodyColumns`：宽了，一行左右两端之间的空白跟着变长；窄了，先截标题，截掉的地方以 `…` 结尾。`Button` 里的字不会自己截断，要按列数自己截。
- 汉字和全角标点占 2 列，其余占 1 列，状态图形按 1 列算。这要求终端把宽度不明确的字符画成 1 格，终端默认都是这样；设成画 2 格的终端里 Claude Code 自己的界面就是错位的，Pane 不为它做处理。图在终端和等宽编辑器里是对齐的；GitHub 网页上汉字不是正好两列，行的右端会参差。
- 图右边、Pane 边界之外的 `◀` 是标注，不画出来。`◀ 焦点` 表示焦点在这一行：引擎把这一行的按钮反色；紧跟着只标 `◀` 的行和它是同一行。`◀ 选中“任务”` 表示那一项加粗并带下划线。
- `e: 执行` 是普通按钮，`e` 是它的快捷键。`[ 我现在该做什么 ] n` 是主按钮，`n` 是它的快捷键。一屏只有一个主按钮。
- 每一节的第一张图画完整的一屏，其余的只画标签页的内容，上面四行不变。输入框上方的图总是四行都画。

### 图形

状态只用这九个图形，颜色是第二重提示，每个图形旁边都另有文字。颜色写的是引擎的主题色。图形后面一定跟一个空格：◐ ▶ ▲ 的字形在有的终端里比一格宽。

| 图形 | 含义 | 颜色 |
| --- | --- | --- |
| □ | 被阻塞 | `dimColor` |
| ◇ | 可执行 | `suggestion` |
| ▶ | 进行中，本 Session | `suggestion` |
| ◐ | 进行中，其他 Session | `inactive` |
| ▲ | Orphaned | `warning` |
| ◈ | Pending Closeout | `warning` |
| ◆ | 已关闭（界面上写“已解锁”） | `warning` |
| ✕ | 读取失败 | `error` |
| ✓ | 有 Acceptance Evidence | `success` |

### 颜色

Pane 不涂底色，颜色全部用引擎的主题色，跟着用户的终端主题走。不写十六进制值，不给 `$.ui.open` 传 `backgroundColor`，根 `Box` 也不设底色。浅色和深色主题下实测都是清楚的。

| 主题色 | 用在 |
| --- | --- |
| 不指定（主题的正文色） | 正文、标题、按钮的标签、选中的标签页 |
| `inactive` | 说明、分组标题、未选中的标签页、编号、主按钮后面的键、Recommendation 的框、树的连线 |
| `dimColor`（`Text` 的属性，不是颜色名） | 被阻塞的 Task 整行；进度条进行中的一段再加上它 |
| `subtle` | 分隔线、普通的框、进度条其余的一段。它很淡，不拿来写字 |
| `suggestion` | 可执行和进行中的图形、项目名、技能命令名、进度条已关闭的一段、“在 GitHub 打开” |
| `warning` | 已关闭、Pending Closeout、“收尾核对”，以及 Orphaned、接管确认、过时的新鲜度 |
| `error` | 读取失败 |
| `success` | Acceptance Evidence |

- “已关闭”和“等你决定”用的是同一个主题色，靠图形区分：◆ ◈ 是前者，▲ 是后者。
- 焦点所在的按钮由引擎反色，不另涂底色。
- `e: 执行` 里的 `e`、冒号和主按钮的方括号由引擎上色，`Button` 没有属性能改。

### 元素

只用 Mods 的 `Box`、`Text`、`Button`、`Link`、`Markdown`。`Select` 获得焦点之后别的快捷键没有反应，所以不用；`Input` 和 `Code` 也没有用到。

| 图里的 | 元素 |
| --- | --- |
| 一行 | 横向的 `Box`，里面是 `Text` 和 `Button` |
| `e: 执行` | `<Button plain hotkey="e" label="执行">` |
| `[ 我现在该做什么 ] n` | `<Button variant="primary" hotkey="n">`。引擎只画方括号里的部分，后面的 `n` 是另写的一个 `inactive` 的 `Text` |
| 能获得焦点的一行（Task、树的节点、技能、`还有 6 个`） | 不带 `hotkey` 的 `Button`，标签是几段 `Text`（图形、编号、标题各用各的颜色），回车按下 |
| `┌─┐` 的框 | `<Box borderStyle="single">`，内宽是 `bodyColumns − 2` |
| `╌` 和 `╎` 围成的框 | `<Box borderStyle="dashed">`，四个角是空的 |
| `────` 分隔线 | `Text`，`─` 重复到 `bodyColumns` |
| 进度条 | 三段 `Text`：`━` 已关闭，`╍` 进行中，`─` 其余；全部关闭时整条 `━` 用 `warning` |
| 树的连线 | `Text`：`├─` `└─` `│`，每一级 3 列 |
| 在 GitHub 打开 | `<Link href>`，里面放一个 `suggestion` 色带下划线的 `Text`。只给 `label` 的话它和正文一个样，看不出是链接 |
| 描述、验收条件、技能原文、回答原文 | `Markdown`，按原文渲染，不改写 |

## 快捷键

`Button` 的 `hotkey` 只能是一个数字或一个小写字母，Pane 取得键盘之后才生效，按钮滚出了视野也有效。同一屏上不出现两个用同一个键的按钮。

| 键 | 动作 | 出现在 |
| --- | --- | --- |
| `1` `2` `3` `4` | 切到 下一步、任务、地图、技能 | 标签页一行，一直在 |
| `r` | 重新读取 | 抬头，一直在 |
| `n` | 我现在该做什么；有了回答之后是“再问一次” | 停靠时在“下一步”里；输入框上方时在第二行右端 |
| `c` | 取消：持有中的请求，或接管确认 | “下一步”持有中；接管确认 |
| `f` | 筛选换到下一项：全部、可执行、进行中、阻塞、已完成 | “任务” |
| `e` | 执行（预填 Execute Prompt）；在技能上是预填技能调用 | 动作栏、返回栏、Recommendation |
| `o` | 钻进 Task 详情或技能原文；输入框上方的 Recommendation 上是看全文 | 动作栏 |
| `t` | 接管 | 焦点在被其他 Session 占用或 Orphaned 的行上时的动作栏；接管确认 |
| `x` | 释放 Occupancy | 焦点在本 Session 进行中或 Orphaned 的行上时的动作栏 |
| `k` | 收尾核对（预填提示词） | Pending Closeout 的 Spec |
| `m` | 打开这一行的 Spec 或 Map 的 Map View | 焦点在“任务”里 Spec 或 Map 的行上时的动作栏 |
| `s` | 打开项目里 Spec 和 Map 的列表，换 Map View 看哪一个 | “地图”，项目里不止一个时 |
| `b` | 返回来的地方 | 返回栏 |
| 上下方向键、Tab | 内容没超出 Pane 时都移动焦点，横排的列表里也是：下是后一项，上是前一项。超出时上下方向键滚动，只有 Tab 移动焦点 | |
| 左右方向键 | 不归 Pane：右没有反应；有后台会话时，左会打开引擎的后台会话列表 | |
| 回车 | 按下焦点所在的按钮；在一行上等于 `o` | |

键盘怎么交给 Pane、怎么还给输入框，由引擎决定（这一版是 ctrl+x tab 和 Esc）。

## 两种位置

终端全屏且不少于 110 列时，Pane 停靠在侧边；否则显示在输入框上方。读 `Pane` 的 `placement`（`dock` 或 `inline`）决定用哪一套。终端在使用中缩到 110 列以下，Pane 会当场换到输入框上方，键盘交还给输入框。

### 停靠在侧边

打开时要 42 列：`$.ui.open({ columns: 42 })`。引擎给的不超过终端列数的 45%，不少于 24 列；不要的话它给得更宽。

从上到下固定是：抬头两行、标签页一行、分隔线、当前标签页的内容。前四行在四个标签页里都不变。

```text
matt-deck · 5e1b7a02               r: 刷新  ◀ 项目（suggestion 加粗）、Session、刷新
本 Session ▶ #16 命令行           3 分钟前  ◀ 本 Session 正在执行的 Task；右端是数据有多新
1:下一步  2:任务  3:地图  4:技能            ◀ 标签页；选中的加粗带下划线
──────────────────────────────────────────
（当前标签页的内容，或钻进去的详情）
```

- 本 Session 没有 Occupancy 时第二行写 `本 Session 没有在执行 Task`。
- 新鲜度写相对时间。超过十分钟用 `warning` 色；读取失败时写 `读取失败`，用 `error` 色。
- **列表不让它超出 Pane。** 内容一超出，引擎就整块滚动：前四行跟着滚走，方向键也从移动焦点变成滚动。所以“任务”“地图”“技能”只画放得下的行，可用的行数是 `scroll.bodyRows` 减去上面固定的几行，放不下的翻页（见“任务”）。
- Task 详情、技能原文、回答原文是拿来读的，可以超出：这时方向键滚动，前四行跟着滚走，`b` 仍然有效。

### 输入框上方

宽而矮，四行。打开时要 4 行：`$.ui.open({ rows: 4 })`。

```text
matt-deck · 5e1b7a02  ▶ #16   ◇ 1 可执行  ▶ 3 进行中  □ 11 阻塞  ◆ 2/17        3 分钟前  r: 刷新  ◀ 第一行
1:下一步  2:任务  3:地图  4:技能                                            [ 我现在该做什么 ] n  ◀ 第二行
（第三行：动作栏。焦点所在的那一项，右端是它的动作）
（第四行：列表排成一行，放得下几项画几项）
```

- 第一行把抬头和计数并成一行：项目、Session、本 Session 正在执行的 Task、可执行、进行中、阻塞、已关闭数比总数、新鲜度、刷新。列数不够时依次省掉：计数后面的字（只留图形和数字）、Session 标识、新鲜度。
- 第二行是标签页，右端是主按钮。推荐请求在持有中、已发出、运行中时，主按钮换成阶段条，四个标签页里都看得到。
- 第三行是动作栏，第四行是排成一行的列表，规则和停靠时一样（见“进入和返回”）。
- “下一步”“任务”“技能”固定四行，不足的补空行，Pane 的高度不随状态变。
- “地图”、Task 详情、技能原文、Recommendation 全文不守四行：前两行不变，下面照停靠时的画法往下排。这时重新打开一次，不带 `rows`，Pane 最多长到 `scroll.bodyRows`（大约是终端行数的三分之一，52 行的终端是 15 行），要更多也不给。按 `b` 或切到别的标签页之后再要回 4 行。
- Pane 往上长，底边贴着输入框；对话区最后几行跟着上移同样的行数，缩回时再下来。
- 这里不画带边框的提示。提示占后两行：第三行是标题和动作，第四行是说明。
- 终端不到 110 列时 Pane 不会自己出现：没有用户操作的打开会被引擎拒绝，要等用户用命令打开，或者终端先宽到过 110 列。

## 进入和返回

- **动作栏。** 列表上面固定有一行动作栏：左边是焦点所在那一行的编号和 triage 标签，右端是对它能做的动作。带快捷键的按钮只放在这里，不放进列表的行里：行里一有别的按钮，方向键就会先走到它们上面，行与行之间的顺序会乱。
- 焦点在行与行之间移动时，只有动作栏的内容在变，列表本身不动。焦点移到别处（标签页、筛选）时，动作栏留着上一次那一行。
- 动作栏里的按钮是用快捷键按的。用方向键或 Tab 走到它们上面要先经过别的行，那时动作栏已经换成那一行的了。
- Pane 取得键盘时，焦点落在当前标签页的第一个可执行 Task 上；没有可执行的，落在第一行。
- 在一行上按回车或 `o`，当前标签页的内容换成详情，抬头和标签页不动。不开弹窗。
- 详情顶上是返回栏：`b: 返回`、来路、这一项的动作。按 `b` 回到来的地方，焦点回到原来那一行，筛选不变。
- 在详情里对“被阻塞”下面的一行按回车，继续钻进那个 Task，来路跟着变长；`b` 一次退一层。
- 在详情里按 `1` 到 `4` 直接切走。再回到这个标签页时看到的是列表。
- 动作只预填：`e` 把 Execute Prompt 或技能调用放进输入框，`k` 把收尾核对的提示词放进输入框，都不发送。只有 `n` 会自己发出请求。

## 解锁

Task 关闭时提示一次。规则来自设计系统里的解锁弹窗；终端里是一行纯文字，不能着色：

```text
◆ 成就已解锁  #15 配置技能  ·  2 / 17
```

- 一次读取发现某个 Task 的 Task Status 从开着变成了已关闭，调用一次 `$.ui.toast`。
- 后面的计数是它所属的 Spec 或 Map 在这次关闭之后的进度。没有上级的 Task 不写计数。
- Spec 自己关闭时也提示，标题写 Spec 的标题。Pending Closeout 不提示。
- 提示过的不再提示。Pane 打开之后的第一次读取只记下现状，所以 Pane 重开、`/clear`、恢复 Session 之后都不补。
- 列表里这一行在下一次重绘时移到“已完成”，图形变成 ◆。
- 这一节没有在真实 Pane 里验证过。

### 任务

从上到下：筛选、动作栏、Spec 和 Map、四个分组。分组的顺序固定是 可执行、进行中、阻塞、已完成，每组标题后面是计数。超过五行的分组只画前五行。

  ━━━━━╍╍╍╍╍╍╍────────────────────────────

▶ #16 命令行                    本 Session

阻塞 11

□ #6  Task 详情                 被 #5 阻塞

- 筛选一行五项：只有“全部”写字，其余是分组的图形加计数，为 0 也写。`f` 换到下一项。
- 每个 Task 一行：图形、编号、标题，右端是状态词、占用它的 Session 或关闭时间。有没有焦点都只占这一行。
- Spec 和 Map 的行排在最前面，占两行：第二行是缩进 2 列的进度条。

#1  待收尾核对        k: 收尾核对  m: 地图  ◀ Pending Closeout 的 Spec

## 在真实 Pane 里验证的结果

2026-11-12 用一个一次性的探针 mod 在 Claude Code 2.1.322 里验证。终端是 cmux（Ghostty 内核，浅色主题），全屏布局，157×52 和 100×52 两种尺寸。上面的画面已经按这些结果改过。验证之后定下来：终端里不固定底色，颜色全部跟终端主题走。

第一版的画面给 Pane 固定了一个深色的底，下面说的“深色底”指的是它。第一版列的八条假设：

| 假设 | 结果 | 上面怎么改的 |
| --- | --- | --- |
| 根 `Box` 的 `backgroundColor` 铺满 Pane 的正文区 | 不成立。只涂到内容所在的行，下面露出终端自己的底色。`$.ui.open({ backgroundColor })` 能铺满 | 不涂底色了，跟随终端主题 |
| `Button` 的标签着色之后，焦点反色仍然清楚 | 成立，前提是标签是带 `color` 的 `Text`：每一段按自己的颜色反色。没着色的标签用终端主题的文字色，浅色主题下在深色底上几乎看不见 | 不涂底色之后，没着色的标签也清楚 |
| `dashed` 边框在窄 Pane 里能看 | 成立，但四个角是空的 | 虚线框改成没有角的画法 |
| 宽度不明确的字符 | 引擎把九个图形、`…` `·` `›` `•`、树的连线和进度条的线都按 1 列排，42 列的行正好排满；Ghostty 里也各占 1 格。◐ ▶ ▲ 的字形比一格宽，会压住后面的空格 | 图形后面一定跟空格。把这类字符设成双宽的终端没有试 |
| 一行是不带 `hotkey` 的 `Button`，靠焦点事件展开第二行 | 重绘跟得上（焦点事件到重绘 3 到 15 毫秒），列表不跳。但第二行里的动作按钮也是焦点环上的一站，方向键会先走到它们上面，展开的行一换，引擎走的顺序就乱 | 行不再展开；动作放进列表上面固定的动作栏。这种摆法实测方向键一行一行走，`e` `o` 对焦点所在的行生效 |
| `Select` 在 36 到 44 列的 Pane 里展开 | 能展开、能选，但它没有颜色属性，浅色主题下在深色底上看不清；它持有焦点时别的快捷键没有反应 | 不涂底色之后看得清，但因为快捷键的问题仍然不用，“切换”改成钻进一个列表 |
| 输入框上方时 Pane 长高再缩回 | 能长能缩，底边贴着输入框往上长，对话区末尾跟着上下移动。最多长到 `scroll.bodyRows`：52 行的终端是 15 行，要 40 行也只给 15 行；`rows: 4` 能压到 4 行 | 写明四行靠 `rows: 4`，长高时最多 `scroll.bodyRows` 行 |
| 输入框上方时 `bodyColumns` 比终端少多少 | 少 4 列：100 列的终端是 96 列 | 不用改 |

验证时另外看到的：

- 主按钮只画 `[ 标签 ]`，不显示快捷键，键仍然有效。图里主按钮后面的键是另写的 `Text`。
- 内容比 Pane 高时，引擎整块滚动：抬头和标签页跟着滚走，方向键变成滚动，只有 Tab 移动焦点（引擎会跟着滚到焦点处），滚出去的按钮快捷键仍然有效。所以列表改成翻页。
- `Button` 里的 `Text` 不会自己截断，长标题会折成两行。`Box` 里的 `Text wrap="truncate-end"` 会截断并补 `…`。
- `$.ui.open({ columns: 42 })` 得到正好 42 列；不要的话 157 列的终端给 69 列。
- 终端缩到 110 列以下，Pane 当场从停靠换到输入框上方，键盘交还给输入框。
- `Text` 支持 `strikethrough`。
- `Markdown` 的正文、标题和列表，还有 `Link` 的 `label`，都由引擎按终端主题上色，浅色主题下在深色底上几乎看不见（行内代码和链接除外）。`Link` 里放带颜色的 `Text` 是清楚的。这是改成跟随终端主题的直接原因。
- 只用主题色、不涂底色的画面另测过一遍：正文、`inactive`、`suggestion`、`warning`、`error`、`success` 写的字，`subtle` 和 `warning` 的框，`Markdown`，没着色的按钮和焦点反色，在浅色主题下都清楚。`subtle` 写字太淡，所以被阻塞的行用 `dimColor`。

同一天第二轮，用另一个探针验证了翻页和横排的列表，上面已经按结果写了：

- **翻页。** 在 `还有 3 个` 上回车能翻页，`前面还有 4 个` 能翻回来。翻页之后焦点留在按下的那个按钮上；最后一页那个按钮没有了，焦点掉回 Pane 的第一个按钮。翻页时调 `$.ui.focus` 把焦点移到新一页的某一行是有效的（返回 `{}`，接着按方向键从那一行往下走）。mod 自己的 `ui.focus` 钩子看不到这次移动，动作栏写哪一行要自己更新。
- **横排的列表。** 输入框上方四行正好放下时，上下方向键和 Tab 在横排的按钮之间走，下是后一项，上是前一项。右方向键没有反应。左方向键把对话送进引擎的后台会话列表（那个界面里 `ctrl+x` 是删除会话），所以不能让用户以为左右能用。翻页、翻页后移焦点、`e` 对焦点所在的项生效，都和停靠时一样。
- **窄终端下的自动打开。** 100 列时，`session.start` 里的 `$.ui.open` 返回 `isPlaced: false`，原因是 `unasked below 110 columns`：要用户自己打开，或者终端先宽过。

第三轮验证了接管确认的焦点：

- **焦点不会自己移过去。** 在行上按 `t`，动作栏换成确认，焦点仍在那一行上。这时回车按下的是那一行（钻进详情），不是确认；`t` 和 `c` 两个快捷键照常有效。
- **`autoFocus` 没有用。** 给确认里的按钮加 `autoFocus`，焦点仍然留在行上：用户已经动过焦点，引擎就不再替他挪。
- **`$.ui.focus` 有用。** 出现时调 `$.ui.focus` 返回 `{}`，焦点落到确认里的按钮上，上下方向键在“接管”和“取消”之间走，回车按下焦点所在的那个。确认或取消之后再调一次移回那一行，也有效。
- 上面写的是移到 `c: 取消` 上，这是为了回车不会误接管，实测移到哪一个都可以。

第四轮验证了深色主题。做法是只给探针会话换主题（`--settings '{"theme":"dark"}'`），只把探针那一个窗口的底色染深，用户自己的设置没有动：

- 只用主题色的那一页在深色主题下同样清楚：正文、`inactive`、`dimColor`、`suggestion`、`warning`、`error`、`success` 写的字，`subtle` 和 `warning` 的框，进度条，`Markdown`，没着色的按钮、主按钮，还有焦点反色。
- `subtle` 在两种主题下写字都太淡，只画线和框的规则不变。
- `warning` 在深色主题下是亮金色，在浅色主题下是深棕色。

第五轮验证了把宽度不明确的字符画成双宽的终端。cmux（Ghostty 1.3.2）没有这个设置，是在系统自带的 Terminal.app 里用一个打开了这一项的临时配置测的，170×50，Pane 停靠，42 列：

- **引擎仍按 1 列排，终端按 2 格画。** □ ◇ ▶ ◐ ▲ ◈ ◆、`…` `·` `•`，还有 `─ │ ┌ ┐ └ ┘ ├ ━` 都占了 2 格。✕ ✓ ›、`╌ ╎ ╍`、汉字和 ASCII 不受影响。
- **坏掉的**：进度条和分隔线画到一半就到了 Pane 的右边；`single` 的框丢了右边框和右边两个角；树的连线每一级宽了一倍；图形后面的字有的行右移了一格。
- **没坏的**：右端对齐的状态词和时间、`dashed` 的框、纯文字的行和按钮。
- **Claude Code 自己的界面在这种终端里也是坏的**：输入框上下的横线各折成了两行，欢迎框只剩几段残缺的边，底部状态栏的文字互相重叠。所以这不是 Pane 能单独解决的，Pane 不为它做处理。

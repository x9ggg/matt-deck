# Codex 标签页布局

Codex 桌面应用的标签页里，Pane 的每个画面怎么排。画面在 [`codex-tab-layout.html`](codex-tab-layout.html)：用浏览器打开，一个画面一个小节，顶上可以换深色和浅色。本文说规则，用画面的编号（`#tasks` 这样的锚点）指过去。

信息结构、状态词、图形和颜色的含义沿用 [`pane-layout.md`](pane-layout.md)，换的只是画法。这里只写画法和 Codex 上不一样的地方；这里没写到的规则（分组怎么分、Spec 那一行取哪个图形、计数数的是哪一批）照 `pane-layout.md`。两处说法不一致时，Codex 的 Pane 以本文为准。

## 怎么读布局稿

- 每个画面宽 638px，是标签页的实测宽度。标着“只画变化的部分”的画面省掉了抬头和标签页，实际都在。
- 画面里的 Task 是示例，编号和标题借自里程碑二，状态是编的。
- 稿子是原生 DOM 加一份样式，没有脚本逻辑（唯一的脚本是换外观的两个按钮）。类名都以 `dk-` 开头，页面照着写同样的结构。
- 样式分四段，段首有注释：颜色间距字体、组件、页面自己、稿子自己的排版。页面要的是前三段；第四段只管这份稿子怎么排，不属于页面。
- 这份样式和 Claude Code 那一侧的网页组件共用，所以里面留着快捷键键帽（`dk-key`）的规则。Codex 的页面不画键帽，稿子里一个也没有。

## 和 Claude Code 上的 Pane 不一样的地方

原因都在宿主：页面只能把文字放进输入框，不能替用户发送；看不到 Session 忙不忙；读不到回答；看不到用户在输入框里敲了什么。

| Claude Code 上 | Codex 上 |
| --- | --- |
| “我现在该做什么”自己发出请求 | 三个动作都只预填，由用户发送 |
| 阶段条：持有中、已发出、运行中、已回答；持有中可以取消 | 阶段条：已填入、等待回报、已回答；没有取消，等 10 分钟停下 |
| 没有回报时显示回答原文 | 只写一句话，回答在对话里 |
| 输入框有草稿时提示，不覆盖 | 不提示：宿主把预填的文字接在草稿后面 |
| 技能写 `/name`，插件提供的带插件前缀 | 技能写 `$name` |
| Session 标识取前 8 位 | 取后 8 位（Codex 的标识开头一段是时间，前后脚开的 Session 前 8 位一样或只差一两位） |
| 每个动作有快捷键 | 第一版没有快捷键，按钮上不画键帽 |
| 手敲 `/implement` 指向被占用的 Task 时提示 | 手敲 `$implement` 时没有提示，那一行照常显示占用它的 Session |
| 列表翻页，不滚动 | 页面照常滚动，不翻页 |
| Task 关闭时提示一次“成就已解锁” | 没有这条提示，里程碑二的规格里没有它 |

另一个宿主的 Session 登记的 Occupancy 两边都看得到。写法：同一个宿主的只写 8 位标识，另一个宿主的前面写宿主名，自己写“本 Session”。Codex 的 Pane 里是 `进行中 · 045b96fc`、`进行中 · Claude Code 3f9c21d0`、`进行中 · 本 Session`。

## 整体

从上到下固定是：抬头、标签页、当前标签页的内容。画面见 `#tasks`。

- **抬头和标签页贴在顶上。** 它们包在 `dk-top` 里，内容在下面滚动，四个标签页里都在。滚动的是页面自己：文档的滚动元素高度等于容器高度，所以 `dk-top` 的 `position: sticky; top: 0` 管用（#68 实测）。
- **宽度跟着标签页。** 内容铺满，不留固定的窄栏；标签页比 720px 宽时，`dk-pane` 限宽 720px 并居中，两边仍是底色。列表一列；成就墙每张卡片不窄于 152px，638px 时三列。
- **深色和浅色都有。** `body` 的 `data-theme` 写 `deck`（深色）或 `deck-light`（浅色），跟宿主的外观走。不写在根元素上：宿主自己往页面根元素的 `data-theme` 写 `light` 或 `dark`，首次加载时晚于页面，会盖掉页面写的值；根元素的这个属性归宿主，页面不读也不写。样式里的选择器不带元素名，写在 `body` 上照样匹配。布局稿不在宿主里，仍写在根元素上。颜色只用样式第一段里的变量，不用宿主给的颜色变量拼：这里的颜色各有固定的含义。
- **不加载外部字体。** 字体栈里 Barlow 和 JetBrains Mono 后面是系统字体，标签页里落在系统字体上。
- **抬头**：项目名、本 Session 的标识、新鲜度、“刷新”。本 Session 有 Occupancy 时，标识后面跟 ▶ 和 Task 编号，点它打开那个 Task 的详情。取的是“进行中”分组里第一个写“进行中 · 本 Session”的 Task：本 Session 占着几个都只写第一个，Orphaned 的不算，Spec 和 Map 不在分组里也不算。它跟着最近一次读到的 Task 列表走：还没读到时不写，读取失败时照上一次读到的写。它是个按钮，Tab 能移到上面；进入详情和点一行一样，来路是当前标签页加编号（`任务 / #74`），已经在详情里的再往里钻一层；正看着的就是这个 Task 的详情时，点它不动。新鲜度写相对时间（“刚刚”“3 分钟前”），超过十分钟加 `is-stale`；读取失败时写“读取失败”，加 `is-failed`；一次读取 10 秒还没结束时写“没有应答”，加 `is-stale`（见“任务”的“读取迟迟没有应答”）。读取期间“刷新”停用，迟了之后恢复可点。
- **标签页**四个：下一步、任务、地图、技能。点击切换，只换下面的内容。
- **鼠标为主。** 每一行、每张卡片的动作常驻在右端，不等悬停。Tab 和回车照浏览器的默认行为，焦点环是 2px 实线。没有快捷键。任务列表的每一行、成就墙的每一张卡片都能拿到焦点；能钻进去的地方都有一个真按钮，键盘照浏览器的默认行为就能走到、按回车进入。
- **重画之后焦点放回原来的控件。** 列表、成就墙、“切换”列表、“下一步”和技能列表每次读取都重画，焦点在里面的，放回重画前它所在的同一个控件：哪个 Task 的哪个按钮、哪一行、哪张卡片按 Task 编号认，“还有 N 个”按分组认，筛选按筛选项认（筛选项不重画，焦点本来就留着），技能列表的行按技能名认、行里的“预填”“原文”按技能名加按钮认。找不到同一个控件（按钮没了，例如 Task 换了状态；或者停用了），放到那个 Task 现在的那一行或那张卡片上、那个技能的那一行上；一次读取读到 `implement` 不能用、“执行”就地停用时也一样，焦点原来在它上面的放到那一行或那张卡片上，没有行和卡片的地方（详情的返回栏、Recommendation）放到这一层第一个能拿焦点的控件上；那一行也没了（例如被筛选掉了，或者技能不在了），放到当前标签页内容里（技能页是技能列表里）第一个能拿焦点的地方。焦点不在被重画的部分里时，重画不动它；页面窗口把焦点交给了宿主（例如人点回了输入框）、焦点在接管确认自己的按钮上或在正要换成确认的那一行、那张卡片上、或者确认刚收起、焦点还等着放回去时，重画也不动它，这几种各有各的规则；接管确认开在别处时，别的行和卡片上的焦点照样放回。放回焦点时页面不滚动。点过“我现在该做什么”之后，焦点落在同一处的“再问一次”上；点“再问一次”之后还在它上面：这两个按钮点下去就停用，浏览器会在下一帧把焦点移走，页面点击时先记下焦点在它上面，重画之后放到接替它的按钮上；人在这期间把焦点移到了别处（页面里别的控件，或者宿主的输入框），就不放，宿主 10 秒没应答、提示“宿主还没应答这次预填”时也一样。“刷新”同样：读取期间它停用，焦点原来在它上面的，读完放回它上面；人在这期间把焦点移到了别处，或者去了宿主，就不放。

## 进入和返回

- 点一行或一张卡片，当前标签页的内容换成详情，顶上是返回栏；抬头和标签页不动。不开弹窗，不开新窗口。行里的按钮不触发钻取。
- 返回栏从左到右：“返回”、来路（`任务 / #70`、`地图 / #64 / #76`、`技能 / $implement`）、这一项的动作、“在 GitHub 打开”。
- “返回”回到来的地方，滚动位置和筛选不变。在详情里点“被阻塞”下面的一行继续往里钻，来路跟着变长，“返回”一次退一层。
- 在详情里点别的标签页就离开详情。再回到这个标签页时看到的是列表。
- 进入时从顶上开始看；“返回”回到进入前滚到的位置，一层一层都是。
- 抬头的“刷新”也重读显示着的这一项；Task 详情还跟着定时的读取重读，技能原文不跟。新的读到之前，上一次读到的留着；第一次读到之前写“正在读取 #70…”，读取失败时写哪一项失败和原因，措辞和“任务”里的读取失败相同。
- 进入和返回时读这一项，也算一次读取：10 秒没回答，照“任务”里的“读取迟迟没有应答”写“没有应答”、出橙框；它还没回答时定时读取不发起，“刷新”重读它（Task 详情的，标签页重新显示时的读取也重读）。离开这一项（返回、换标签页），它就不再算迟。
- 重读到的和上次画出时一样（这一项自己的读取，和任务列表里它的那一项都没变），页面不动：选中的文字、焦点和按钮都留着。变了才整层重画；焦点原来在返回栏的某个动作上、重画后这个动作还在的，焦点放回去。焦点原来在内容里的也放回：“被阻塞”下面的行按 Task 编号认，“属于”按它自己认，描述和验收条件里的链接按钮按它是其中第几个认；找不到的，放到“返回”上。页面窗口把焦点交给了宿主时不放。接管确认自己的焦点照它的规则。放回时页面不滚动。
- 读到过内容的这一项重读失败时，红框提示放在返回栏下面、内容最上面，读到过的内容留在提示下面；下一次读成功，提示消失。第一次就失败的，只有提示。Task 详情开着时读任务列表失败，“任务”里那条“读取 Task 失败”的提示也放在详情上面。
- 同一项的几次读取重叠时，只画最后发起的那次的回答，之前的晚到了也丢掉。
- 技能原文里的“预填”跟着最新读到的技能走：一次读取（定时的、标签页重新显示时的、“刷新”的，见“技能”）读到这个技能不再是同一份、已经不在 Skill Source 里，或者读不到 Skill Source 时，它马上停用，不等技能原文重读回来。预填之后的 5 秒按填进去的东西记，见“预填”。
- “在 GitHub 打开”经宿主打开：页面发 `ui/open-link`，宿主在默认浏览器里打开（#68 实测）。地址用 Deck 服务读到的，页面不拼；页面里不放普通链接。宿主拒绝打开时，结果提示（见“预填”）的标题是“没有打开链接”，说明是“宿主拒绝了这次打开：<宿主给的原因>。再点一次重试。”，宿主没给原因时冒号和原因一起省掉；再点“在 GitHub 打开”时先收起它。宿主一直不回答时页面不做什么：点击不停用任何按钮。
- 页面里这套机制只有一份（`plugin/codex/pane.html` 的 `enter`、`back`、`drawStep`），Task 详情和技能原文都用它。别的视图进入时交给它这一层在来路里的名字和怎么画这一层；从成就墙进入的还交上中间那一层（`地图 / #64 / #76` 里的 `#64`）。返回栏、来路、“返回”和滚动位置都由它管。

## 预填

“我现在该做什么”“执行”“预填”“收尾核对”“配置这个项目”“重跑配置”都是把文字放进输入框，由用户发送。文字由 Deck 服务给，页面不拼。

- 预填的按钮点过之后停用，宿主收下之后字换成“已填入”，停用 5 秒，然后换回。画面见 `#tasks-filled`。这样连点两下不会往输入框里填两份。这几秒按填进去的东西记，不按按钮记：同一个 Task 的“执行”（还有“接管”），同一个技能的“预填”（“技能”里那一行和技能原文里的），所有“重跑配置”和“配置这个项目”（填的都是配置技能的调用），同一个 Spec 的“收尾核对”（行上、详情返回栏里、档案卡上），各自一起停用、一起写“已填入”。读取重画、换标签页、进出详情都不影响。点下去时焦点在这个按钮上的（行、卡片、Task 详情和技能原文的返回栏、档案卡、各条提示、Recommendation 的“执行这个 Task”，画在哪里都算），浏览器在它停用时把焦点移走；它恢复可点时（宿主拒绝是马上，10 秒没应答是那时，填入之后是 5 秒后），焦点放回这个位置现在的那个按钮上，期间重画过的，是新画出的那个；那个位置已经没有这个按钮、或者它因别的原因停用的，放到那一行、那张卡片或那个技能的那一行上，没有行和卡片的地方（详情的返回栏、Recommendation）放到这一层第一个能拿焦点的控件上。只在焦点还落在页面上、页面窗口没有把焦点交给宿主时才放；人把焦点移到了别处（页面里别的控件，或者宿主的输入框），或者换了标签页、进入或退出了详情，就不放。接管确认里的“接管”照接管确认的规则。
- “我现在该做什么”例外：宿主收下之后进入等待，见“下一步”。
- 对被其他 Session 占用的 Task 点“接管”或“执行这个 Task”，先出接管确认，见“任务”。
- **宿主拒绝预填**（`#tasks-refused`）：按钮马上换回原来的字、恢复可点，不写“已填入”。结果提示的标题是“没有填入输入框”，说明是“宿主拒绝了这次预填：<宿主给的原因>。再点“<按钮上的字>”重试。”；宿主没给原因时，冒号和原因一起省掉。原因原样显示，句子是 Pane 的。“我现在该做什么”和“再问一次”被拒时不用结果提示，见“下一步”。
- **Deck 服务没给出 Execute Prompt**：点“执行”（行上、卡片上、详情的返回栏里）或“执行这个 Task”时，`deck_execute` 回答失败或工具报错，不发预填，按钮马上恢复可点。结果提示的标题是“没有填入输入框”，说明照原因写：Skill Source 里没有 implement 时是“Skill Source 里没有 implement。重跑配置之后恢复。”；找不到 Skill Source 时是“找不到 Skill Source。重跑配置之后恢复。”，和技能页那句相同；工具报错时是“Deck 服务出错：<原因>。再点“<按钮上的字>”重试。”。原因原样显示，句子是 Pane 的。同时马上重读一次，和释放之后的那次一样，不是“刷新”：读到 `implement` 不能用的，各处“执行”随之停用，“执行”不能用的那条提示和它的“重跑配置”随之出现，不等 60 秒的定时读取；结果提示不因这次读取收起。
- **Deck 服务 10 秒没有应答**：点“执行”“执行这个 Task”“接管”“释放”或“我现在该做什么”“再问一次”之后，`deck_execute`、`deck_occupy`、`deck_release` 或 `deck_ask` 发出 10 秒还没有回答，点的那个按钮换回原来的字、恢复可点，和它一起停用的也恢复；出一条橙框的提示，画法同下一条，标题“Deck 服务还没应答。”。10 秒之前照旧停用，没有提示。说明按动作：
  - “执行”“执行这个 Task”：在结果提示的位置，“回答到了会照常填入；不想等就再点“<按钮上的字>”。”。接管之后的那一次：“#72 已转给本 Session。回答到了会照常填入 Execute Prompt；不想等就点“释放”之后再点“执行”。”。
  - “接管”：接管确认还开着的，确认里两个按钮恢复，焦点原来在“接管”上的回到它上面，确认的说明换成“Deck 服务还没应答。回答到了会照常接管；不想等就再点“接管”。”；确认已经收起的（换了标签页，或者进入、退出了详情），在结果提示的位置，说明是“回答到了会照常接管；不想等就再点“接管”。”，那一行的“接管”恢复。
  - “释放”：在结果提示的位置，“回答到了会照常释放；不想等就再点“释放”。”。“释放”本来就不停用：10 秒之内又点了一次的，两次的回答都照常处理，前一次到 10 秒还没回答时同样出这条提示，它的回答到了时收起；出了这条提示之后再点的，才算再点过。
  - “我现在该做什么”“再问一次”：见“下一步”。
  - 之后回答才到、期间没有再点同一个的（“执行”和“接管”按 Task，“释放”按 Task，`deck_ask` 按“下一步”最后一次问的），照常往下做，提示收起：Execute Prompt 和推荐请求填进输入框，宿主的 10 秒从这时另算；接管照常重读、填 Execute Prompt；释放照常重读。回答是失败的，照各自的失败提示写（“#72 没有接管”“#74 没有释放”，以及上面“Deck 服务没给出 Execute Prompt”）。期间再点过的，前一次的回答丢掉，不往下做，输入框里不会有两份；接管确认里点了“取消”的也算放弃，回答丢掉（见“任务”的接管确认）。

- 同一时间只有一条，新的换掉旧的。

**接管确认**（`#tasks-takeover`、`#tasks-takeover-host`、`#tasks-takeover-orphaned`）。对其他 Session 占用的或 Orphaned 的 Task 点“接管”（行上、卡片上、详情的返回栏里），或者在 Recommendation 里对它点“执行这个 Task”时，点的那个位置上换成一条提示：行的位置、卡片的位置、详情的返回栏下面、Recommendation 主按钮的位置。列表的其余部分不动。

- 标题说谁在执行：`#72 正由 Session 045b96fc 执行`；另一个宿主的 Session 写成 `#69 正由 Claude Code 3f9c21d0 执行`；Orphaned 的写 `#75 的 Session 已结束`。说明都是“接管会把 Occupancy 转给本 Session。”
- 两个按钮：“接管”和“取消”。提示出现时焦点落在“取消”上。
- 点“接管”：Occupancy 转给本 Session，再把 Execute Prompt 填进输入框；转移进行中“取消”和“接管”一同停用，转移结束后恢复；Deck 服务 10 秒没有应答时也恢复，说明换成没有应答的那句（见“预填”）。点“取消”：提示收起，什么都不变。没有应答之后点的“取消”算放弃这次接管：之后到的回答丢掉，不填 Execute Prompt，也不出提示；Occupancy 要是已经转了，下一次读取把这个 Task 画成本 Session 的。
- “接管”和“执行”一同停用：`implement` 不能用时（见下面“执行不能用”一段），以及这个 Task 的 Execute Prompt 正在填入、填入后的 5 秒里。

**读取失败**（`#tasks-error`）。新鲜度的位置写“读取失败”。内容最上面是一条红框的提示，带 ✕（只画给眼睛看，读屏读标题和说明）：标题说哪一步失败，说明说原因和怎么修，例如“`gh` 未登录。运行 `gh auth login` 后点“刷新”重试。”。提示里不放按钮，重试用抬头的“刷新”。例外是技能页的“找不到 Skill Source”（`#skills-missing`）：要修的是配置，不是重试，所以标题那一行右端是“重跑配置”。之前读到过数据时，旧列表留在提示下面。

**正在读取**（`#tasks-loading`）。第一次读取返回之前，内容的位置写一行“正在读取 Task…”；项目配置还没读到时写“正在读取项目配置…”。

**读取迟迟没有应答**（`#tasks-slow`）。一次读取（定时的、标签页重新显示时的、“刷新”的，以及页面自己发起的：点开“技能”或“下一步”时读技能、进入或返回时读 Task 详情或技能原文）开始 10 秒还没结束，算迟。它等的可能是项目配置、Task、技能、Task 详情或技能原文里的任何一个。

- 抬头新鲜度的位置写“没有应答”，用过时的那种橙色（`is-stale`）。
- 当前标签页的内容最上面放一条橙框提示，画法和“执行”不能用的那条一样：标题“Deck 服务还没应答。”，说明“点“刷新”重新读取。”。四个标签页、详情和未配置项目的画面里都在这个位置。第一次读取就迟了的，“正在读取项目配置…”或“正在读取 Task…”那一行换成这条提示。
- “刷新”恢复可点。“刷新”、标签页重新显示时的读取、接管和释放之后的重读，迟了之后马上开始，不等那次迟的读取结束；那次迟的读取之后到的回答丢掉，不画。
- 60 秒的定时读取不取代迟的读取：最后开始的那次读取迟了、还没回答时，定时读取不发起；它回答之后，定时读取从下一个 60 秒的点照常发起。
- 迟了之后没有新的读取开始的，晚到的回答照常画出来，提示和“没有应答”随之消失，新鲜度照常写。慢而没丢的读取（例如 `gh` 慢），慢过 60 秒的也一样，因此不会永远看不到。
- 回答真的丢了（再也不回）时，自动读取停住：抬头一直写“没有应答”，橙框一直在，直到人点“刷新”，或者把标签页藏起再显示。
- 迟了之后新的一次读取开始时，“没有应答”和提示留着，要等它结束才消失；这期间“刷新”停用。
- 迟的读取后面还排着别的读取时（接管、释放之后的重读），“刷新”要等排着的那次结束或也迟了才恢复。
- 接管之后的那次重读迟了、又被新的读取取代的，不填 Execute Prompt，等它的回答到了，结果提示说接管之后没有读到 Task（见“预填”）；下一次读到时这个 Task 画成本 Session 的。
- 读取没迟的时候，定时读取和标签页重新显示时的读取照旧不发起另一次。

## Task 详情

对应 #70。整屏见 `#detail`。

- 从上到下：返回栏、标题（编号用状态的颜色）、状态那一行、“属于”、四个小节。
- 状态那一行把三件事分开放：Task Status、Execution Status（没有 Occupancy 就不放）、Acceptance Evidence（没有就不放）；后面是 triage 标签、指派人、时间。没有指派人写“未指派”。

- **描述和验收条件按 Markdown 画**，只认下面这些语法，页面用自己的元素和文字搭出来，不把正文当 HTML。描述认块级和行内的，验收条件每一项只认行内的，一项里的 `#` 不当标题。

  - 行内：反引号括起来的行内代码，`**粗**`，`*斜*` 和 `_斜_`（夹在字母数字中间的下划线不算），`[文字](地址)` 和裸写的地址。
  - 链接只认以 `http://` 或 `https://` 开头、后面跟着主机的地址，画成和“属于”那样带下划线的按钮，点它和“在 GitHub 打开”一样经宿主打开：发 `ui/open-link`，宿主拒绝时出同一条“没有打开链接”的结果提示（见“进入和返回”）。别的地址，例如 `javascript:`、`mailto:`、相对路径、只有 `http://` 的，整个链接都当文字。`[文字](地址)` 的文字不跨行、不含方括号、最多 256 个字；地址不含空白和方括号，可以有成对的圆括号，括号里不再有括号和空白，连括号最多 2048 个字（例如 `[x](https://en.wikipedia.org/wiki/Foo_(bar))` 打开带 `(bar)` 的整个地址）。不合这些的，`[文字](地址)` 这一层当文字，里面的 http(s) 地址仍照裸地址认成按钮。裸地址同样认成对的一层圆括号，到空白、不成对的括号或末尾的标点为止：`(见 https://example.com/a)` 的按钮是 `https://example.com/a`，外面那对括号是文字；`见 https://en.wikipedia.org/wiki/Foo_(bar)。` 的句号不算进地址；嵌套两层的括号（`a_((b))`）不认，在括号前截断。这样不论正文是什么，画它的时间都只和长度成正比。`[文字](地址)` 画成的按钮，`title` 是它要打开的地址，原样，文字像一个地址、却指向别处时也看得出来；裸地址的按钮字面就是地址，不加 `title`。徽章 `[![替代文字](图片地址)](链接地址)`，链接地址合上面的要求时画成一个链接按钮：字是替代文字，替代文字是空的就用链接地址，点它打开链接地址，`title` 同上；图片不请求，页面里不出图片元素。链接地址不是 http(s) 或没有主机的，整段当文字；链接地址不合上面的写法的（例如有空白、括号套了两层、太长），和 `[文字](地址)` 一样，这一层当文字，里面的 http(s) 地址照裸地址认。链接的文字里不再认链接。正文里 `#88` 这样的编号不做成链接。
  - 没认的语法，例如表格、单独的图片 `![a](b)`、HTML 标签、删除线，一律当文字原样显示，不多出元素，也不发请求。嵌套的强调只认里面那一层：`*斜 **粗** 斜*` 画成文字 `*斜 `、粗体“粗”和文字 ` 斜*`。引用里只认行内语法：`> - a` 画成引用里的一段“- a”，不是列表。
  - 技能原文不按 Markdown 画，见“技能”。
- “被阻塞”一行一个阻塞者：它自己的状态图形、编号、标题。点它钻进那个 Task。这一行本身是按钮，画出来的样子不变。
- 验收条件的每一项前面有一段只给读屏的字，“已勾”或“未勾”，看不见；已勾的方框照旧填色。

- `implement` 不能预填时，返回栏下面放“执行”不能用的那条提示（`#detail-noexec`），和“任务”里的一样；接管确认开着时，确认排在它下面。

## 地图

对应 #71、#78。整屏见 `#map`。

顶上一张档案卡说这是哪个 Spec 或 Map、进度多少，下面是 Child Task 的成就墙，一张卡片一个 Child Task。

- **档案卡**从上到下：种类和编号、标题、一句目标（正文里第一个文字段落的第一句：代码块（围栏的和缩进四格或一个制表符的）、列表（列表项下面隔着空行、缩进两格以上的段落也算列表的）、引用、表格（有没有前导竖线都算，靠下一行的分隔行认）、`<details>` 到 `</details>` 那一行、别的 HTML 块、链接和脚注的定义行、只有图片的行和分隔线都跳过；行内 Markdown 还原成文字：行内的 HTML 标签去掉、`<br>` 换成空格，`<!-- … -->` 去掉，`<https://…>` 留下地址，删除线、引用式链接留下文字，引用式图片和脚注记号去掉，`&amp;` 这类常见实体和数字实体换成它代表的字符；还原后只剩空白或零宽字符的段落（比如一排带链接的徽章）也跳过；英文句点后面接小写字母时不算句末；最多两行，超出的用省略号，和标题一样；没有文字段落就省略）、四个计数、解锁进度。进度的数字是这一屏里最大的字。

## 宿主给页面的

#68 在真实的桌面应用（26.1117.41037）里，从标签页中的页面读到的。页面只用到下面写明的几样。

- **握手结果**的 `hostContext` 里有 `theme`（`light` 或 `dark`）、`displayMode`（`fullscreen`）、`containerDimensions`（那次是宽 638、高 1034）、`locale`、`timeZone` 和 `styles.variables`（76 个颜色和字体变量）。页面只读 `theme`，见“整体”的深色和浅色；宽度跟着标签页走，不读 `containerDimensions`。

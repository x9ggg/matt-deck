# Codex 标签页布局

Codex 桌面应用的标签页里，Pane 的每个画面怎么排。画面在 [`codex-tab-layout.html`](codex-tab-layout.html)：用浏览器打开，一个画面一个小节，顶上可以换深色和浅色。本文说规则，用画面的编号（`#tasks` 这样的锚点）指过去。

信息结构、状态词、图形和颜色的含义沿用 [`pane-layout.md`](pane-layout.md)，换的只是画法。这里只写画法和 Codex 上不一样的地方；这里没写到的规则（分组怎么分、Spec 那一行取哪个图形、计数数的是哪一批）照 `pane-layout.md`。两处说法不一致时，Codex 的 Pane 以本文为准。

## 怎么读布局稿

- 每个画面宽 638px，是标签页的实测宽度。标着“只画变化的部分”的画面省掉了抬头和标签页，实际都在。
- 画面里的 Task 是示例，编号和标题借自里程碑二，状态是编的。
- 稿子是原生 DOM 加一份样式，没有脚本逻辑（唯一的脚本是换外观的两个按钮）。类名都以 `dk-` 开头，页面照着写同样的结构。
- 样式分四段，段首有注释：颜色间距字体、组件、页面自己、稿子自己的排版。页面要的是前三段；第四段只管这份稿子怎么排，不属于页面。
- 这份样式和 Claude Code 那一侧的网页组件共用，所以里面留着快捷键键帽（`dk-key`）的规则。Codex 的页面不画键帽，稿子里一个也没有。

## 和 Claude Code 上的 Pane 不一样的地方

原因都在宿主：页面只能把文字放进输入框，不能替用户发送；看不到 Session 忙不忙；读不到回答；看不到用户在输入框里敲了什么。

| Claude Code 上 | Codex 上 |
| --- | --- |
| “我现在该做什么”自己发出请求 | 三个动作都只预填，由用户发送 |
| 阶段条：持有中、已发出、运行中、已回答；持有中可以取消 | 阶段条：已填入、等待回报、已回答；没有取消，等 10 分钟停下 |
| 没有回报时显示回答原文 | 只写一句话，回答在对话里 |
| 输入框有草稿时提示，不覆盖 | 不提示：宿主把预填的文字接在草稿后面 |
| 技能写 `/name`，插件提供的带插件前缀 | 技能写 `$name` |
| Session 标识取前 8 位 | 取后 8 位（Codex 的标识开头一段是时间，前后脚开的 Session 前 8 位一样或只差一两位） |
| 每个动作有快捷键 | 第一版没有快捷键，按钮上不画键帽 |
| 手敲 `/implement` 指向被占用的 Task 时提示 | 手敲 `$implement` 时没有提示，那一行照常显示占用它的 Session |
| 列表翻页，不滚动 | 页面照常滚动，不翻页 |
| Task 关闭时提示一次“成就已解锁” | 没有这条提示，里程碑二的规格里没有它 |

另一个宿主的 Session 登记的 Occupancy 两边都看得到。写法：同一个宿主的只写 8 位标识，另一个宿主的前面写宿主名，自己写“本 Session”。Codex 的 Pane 里是 `进行中 · 045b96fc`、`进行中 · Claude Code 3f9c21d0`、`进行中 · 本 Session`。

## 整体

从上到下固定是：抬头、标签页、当前标签页的内容。画面见 `#tasks`。

- **抬头和标签页贴在顶上。** 它们包在 `dk-top` 里，内容在下面滚动，四个标签页里都在。滚动的是页面自己：文档的滚动元素高度等于容器高度，所以 `dk-top` 的 `position: sticky; top: 0` 管用（#68 实测）。
- **宽度跟着标签页。** 内容铺满，不留固定的窄栏；标签页比 720px 宽时，`dk-pane` 限宽 720px 并居中，两边仍是底色。列表一列；成就墙每张卡片不窄于 152px，638px 时三列。
- **深色和浅色都有。** `body` 的 `data-theme` 写 `deck`（深色）或 `deck-light`（浅色），跟宿主的外观走。不写在根元素上：宿主自己往页面根元素的 `data-theme` 写 `light` 或 `dark`，首次加载时晚于页面，会盖掉页面写的值；根元素的这个属性归宿主，页面不读也不写。样式里的选择器不带元素名，写在 `body` 上照样匹配。布局稿不在宿主里，仍写在根元素上。颜色只用样式第一段里的变量，不用宿主给的颜色变量拼：这里的颜色各有固定的含义。
- **不加载外部字体。** 字体栈里 Barlow 和 JetBrains Mono 后面是系统字体，标签页里落在系统字体上。
- **抬头**：项目名、本 Session 的标识、新鲜度、“刷新”。本 Session 有 Occupancy 时，标识后面跟 ▶ 和 Task 编号，点它打开那个 Task 的详情。新鲜度写相对时间（“刚刚”“3 分钟前”），超过十分钟加 `is-stale`；读取失败时写“读取失败”，加 `is-failed`。读取期间“刷新”停用。
- **标签页**四个：下一步、任务、地图、技能。点击切换，只换下面的内容。
- **鼠标为主。** 每一行、每张卡片的动作常驻在右端，不等悬停。Tab 和回车照浏览器的默认行为，焦点环是 2px 实线。没有快捷键。

## 进入和返回

- 点一行或一张卡片，当前标签页的内容换成详情，顶上是返回栏；抬头和标签页不动。不开弹窗，不开新窗口。行里的按钮不触发钻取。
- 返回栏从左到右：“返回”、来路（`任务 / #70`、`地图 / #64 / #76`、`技能 / $implement`）、这一项的动作、“在 GitHub 打开”。
- “返回”回到来的地方，滚动位置和筛选不变。在详情里点“被阻塞”下面的一行继续往里钻，来路跟着变长，“返回”一次退一层。
- 在详情里点别的标签页就离开详情。再回到这个标签页时看到的是列表。
- 进入时从顶上开始看；“返回”回到进入前滚到的位置，一层一层都是。
- 抬头的“刷新”也重读显示着的这一项；Task 详情还跟着定时的读取重读，技能原文不跟。新的读到之前，上一次读到的留着；第一次读到之前写“正在读取 #70…”，读取失败时写哪一项失败和原因，措辞和“任务”里的读取失败相同。
- “在 GitHub 打开”经宿主打开：页面发 `ui/open-link`，宿主在默认浏览器里打开（#68 实测）。地址用 Deck 服务读到的，页面不拼；页面里不放普通链接。
- 页面里这套机制只有一份（`plugin/codex/pane.html` 的 `enter`、`back`、`drawStep`），Task 详情和技能原文都用它。别的视图进入时交给它这一层在来路里的名字和怎么画这一层；从成就墙进入的还交上中间那一层（`地图 / #64 / #76` 里的 `#64`）。返回栏、来路、“返回”和滚动位置都由它管。

## 预填

“我现在该做什么”“执行”“预填”“收尾核对”“配置这个项目”“重跑配置”都是把文字放进输入框，由用户发送。文字由 Deck 服务给，页面不拼。

- 预填的按钮点过之后停用，宿主收下之后字换成“已填入”，停用 5 秒，然后换回。画面见 `#tasks-filled`。这样连点两下不会往输入框里填两份。
- “我现在该做什么”例外：宿主收下之后进入等待，见“下一步”。
- 对被其他 Session 占用的 Task 点“接管”或“执行这个 Task”，先出接管确认，见“任务”。
- **宿主拒绝预填**（`#tasks-refused`）：按钮马上换回原来的字、恢复可点，不写“已填入”。结果提示的标题是“没有填入输入框”，说明是“宿主拒绝了这次预填：<宿主给的原因>。再点“<按钮上的字>”重试。”；宿主没给原因时，冒号和原因一起省掉。原因原样显示，句子是 Pane 的。“我现在该做什么”和“再问一次”被拒时不用结果提示，见“下一步”。
- **接管之后 Execute Prompt 被拒**：Occupancy 已经转给本 Session，页面不再自己改它，也不加按钮。结果提示的标题是“#72 已转给本 Session，Execute Prompt 没有填入”，说明先写“宿主拒绝了这次预填：<原因>。”，再写“点“释放”之后再点“执行”，或者把下面这段 Execute Prompt 填进输入框自己发送。”，下面原样附上 Deck 服务给的那段 Execute Prompt，等宽，保留换行。

**结果提示**是一个动作没做成时的那条提示。它放在贴顶的那一块（`dk-top`）的最下面：标签页下面；未配置的项目没有标签页，就在抬头下面。它跟着抬头一起贴顶，页面滚到哪里都看得见，四个标签页、详情和未配置项目的画面都用这一个位置。

- 画法和读取失败的提示一样：红框，带 ✕，标题说没做成什么，说明写原因和怎么重试，`role="status"`。提示里不放按钮。
- 同一时间只有一条，新的换掉旧的。
- 下一次预填、接管或释放一开始，先把它收起；换标签页、进入或退出详情时也收起。定时读取、标签页重新显示时的读取和“刷新”都不动它。

## 下一步

对应 #73。

| 画面 | 什么时候 | 画什么 |
| --- | --- | --- |
| `#next-idle` | 没有请求 | 主按钮“我现在该做什么”，下面一句“把 $ask-matt 填进输入框，附带 Task Snapshot。” |
| `#next-waiting` | 点过主按钮 | 阶段条停在“等待回报”，下面写“已填入输入框，等你发送。”，右边是普通按钮“再问一次” |
| `#next-answered` | 收到回报 | 阶段条走完，下面是 Recommendation 的卡片，卡片下面是“再问一次” |
| `#next-timeout` | 等了 10 分钟 | “等待回报”那一格划线（`is-cancelled`），写“等了 10 分钟，没有收到回报，已停止等待。回答在对话里。”，主按钮回来 |
| `#next-unavailable` | `ask-matt` 不能预填 | 主按钮停用，下面一句原因和普通按钮“重跑配置” |

- 阶段条三格：`已填入`、`等待回报`、`已回答`。走过的格加 `is-done`，当前的加 `is-now`。
- 没有取消，没有忙碌状态。“再问一次”在等待期间和停止之后都能点，点了重新填入、重新计时，旧请求之后到的回报不显示。
- 宿主收下预填之后才进入等待、开始读回报。“我现在该做什么”或“再问一次”被宿主拒绝时，阶段条留在点之前的样子，不读这次请求的回报；正在等的那次照旧等。原因写在“没有填入推荐请求”那条红框提示里（Deck 服务做不出请求时也用它），说明是“宿主拒绝了这次预填：<原因>。再点“<按钮上的字>”重试。”。
- 等待期间点过“再问一次”之后，`#next-waiting` 里那句话换成“已重新填入。输入框里上一份还在的话，先删掉再发送。”。宿主把新的一份接在后面，页面看不到输入框，只能提醒。
- Recommendation 的卡片：眉题“下一个成就”、Task 的标题和编号、四个字段（下一步、技能、理由、阻塞）、主按钮“执行这个 Task”。字段没有内容时写“无”，不省略。技能名照 Codex 的写法。
- 推荐的 Task 被其他 Session 占用或是 Orphaned 时，点“执行这个 Task”先出接管确认，画在主按钮的位置上。
- 原因的两种写法：“Codex 里找不到 ask-matt，不能预填。”和“Codex 里的 ask-matt 不是同一份，不能预填。”

## 任务

对应 #69、#74、#76、#78。整屏见 `#tasks`。

从上到下：筛选、Spec 和 Map 的行、四个分组。分组的顺序固定是可执行、进行中、阻塞、已完成，每组标题后面是计数。

- **筛选**一行五项，单选：全部和四个分组，计数写在筛选项上，为 0 也写。选中一个分组时只画这个分组，不画分组标题，全部画出。
- **超过五行的分组**只画前五行，下面是“还有 2 个”。它是个按钮，点它等于把筛选换到这个分组。
- **每个 Task 两行**：第一行是编号和标题，标题最多两行；第二行左边是状态词和 triage 标签，右边是动作。点这一行进详情。
- 鼠标所在或有焦点的那一行多出一个“详情”。已经有两个动作的行不加。
- 带 `needs-triage` 或 `needs-info`、没有 Occupancy 的 Task 在“阻塞”里，画法和被阻塞的一样；没有阻塞者时第二行不写状态词，只有这个标签。
- **Spec 和 Map 的行**排在最前面，左边一条竖线，第一行在编号前写种类，右端是进度环和 `4/17`；第二行是各分组的计数，动作是“地图”，打开它的 Map View。

| 这一行的状态 | 状态词 | 动作 |
| --- | --- | --- |
| 可执行 | `可执行` | 执行 |
| 本 Session 占用 | `进行中 · 本 Session` | 释放 |
| 其他 Session 占用 | `进行中 · 045b96fc` 或 `进行中 · Claude Code 3f9c21d0` | 接管 |
| Orphaned | `Orphaned` | 接管、释放 |
| 被阻塞 | `被 #72 阻塞`，阻塞者写全 | 没有 |
| 已关闭 | `已解锁`，有 Acceptance Evidence 时加 ✓ 和“验收证据” | 没有，右端写关闭时间 |
| Spec 或 Map | 各分组的计数 | 地图 |
| Pending Closeout 的 Spec | `待收尾核对` | 收尾核对、地图 |

**接管确认**（`#tasks-takeover`、`#tasks-takeover-host`、`#tasks-takeover-orphaned`）。对其他 Session 占用的或 Orphaned 的 Task 点“接管”（行上、卡片上、详情的返回栏里），或者在 Recommendation 里对它点“执行这个 Task”时，点的那个位置上换成一条提示：行的位置、卡片的位置、详情的返回栏下面、Recommendation 主按钮的位置。列表的其余部分不动。

- 标题说谁在执行：`#72 正由 Session 045b96fc 执行`；另一个宿主的 Session 写成 `#69 正由 Claude Code 3f9c21d0 执行`；Orphaned 的写 `#75 的 Session 已结束`。说明都是“接管会把 Occupancy 转给本 Session。”
- 两个按钮：“接管”和“取消”。提示出现时焦点落在“取消”上。
- 点“接管”：Occupancy 转给本 Session，再把 Execute Prompt 填进输入框；转移进行中“取消”和“接管”一同停用，转移结束后恢复。点“取消”：提示收起，什么都不变。
- “接管”和“执行”一同停用：`implement` 不能用时（见下面“执行不能用”一段），以及这个 Task 的 Execute Prompt 正在填入、填入后的 5 秒里。
- 没有接管成：Deck 服务说了原因的，提示留着，说明换成原因，末尾是“再点“接管”重试。”；Task 已关闭或不在了，或者已经转给第三个 Session，提示收起，列表照重新读到的画。
- 换标签页、进入或退出详情时提示收起；这个 Task 不再被其他 Session 占用时（被释放、已关闭）也收起。
- “释放”不用确认，点了直接释放。接管和释放之后都重新读一次 Task。接管成了、这次读取却出错的，不填 Execute Prompt，下一次读到时这个 Task 画成本 Session 的。

**Pending Closeout**（`#tasks-closeout`）。Child Task 全部关闭而 Spec 还开着：这一行换成金色虚线框，图形是 ◈，进度环走满，状态词写“待收尾核对”，动作是金色的“收尾核对”和“地图”。不写“已完成”，不写“验收通过”。

**“执行”不能用**（`#tasks-noexec`）。Codex 里找不到 `implement`，或者找到的不是 Skill Source 里的那一份时，内容最上面放一条提示，右端是“重跑配置”。标题是“Codex 里找不到 implement，不能预填执行。”或“Codex 里的 implement 不是同一份，不能预填执行。”，说明是“所有 Task 的“执行”先停用，重跑配置之后恢复。”。每一行、每张卡片和 Recommendation 里的“执行”停用，原因不在行上重复。“地图”标签页里同样在内容最上面放这一条。

**空列表**不是报错，一句事实加一句去处，画在虚线框里。

| 画面 | 什么时候 | 两句话 |
| --- | --- | --- |
| `#tasks-empty` | Task Source 里一个 Task 都没有 | Task Source 里还没有 Task。在 Session 里用 Matt skills 建立。 |
| `#tasks-empty-group` | 筛选到“可执行”，是空的 | 没有可执行的 Task。到“下一步”问该做什么。 |
| | 筛选到“进行中”，是空的 | 没有进行中的 Task。点上面的筛选看别的分组。 |
| | 筛选到“阻塞”，是空的 | 没有被阻塞的 Task。点上面的筛选看别的分组。 |
| | 筛选到“已完成”，是空的 | 还没有已完成的 Task。点上面的筛选看别的分组。 |

**读取失败**（`#tasks-error`）。新鲜度的位置写“读取失败”。内容最上面是一条红框的提示，带 ✕：标题说哪一步失败，说明说原因和怎么修，例如“`gh` 未登录。运行 `gh auth login` 后点“刷新”重试。”。提示里不放按钮，重试用抬头的“刷新”。之前读到过数据时，旧列表留在提示下面。

**正在读取**（`#tasks-loading`）。第一次读取返回之前，内容的位置写一行“正在读取 Task…”；项目配置还没读到时写“正在读取项目配置…”。

## Task 详情

对应 #70。整屏见 `#detail`。

- 从上到下：返回栏、标题（编号用状态的颜色）、状态那一行、“属于”、四个小节。
- 状态那一行把三件事分开放：Task Status、Execution Status（没有 Occupancy 就不放）、Acceptance Evidence（没有就不放）；后面是 triage 标签、指派人、时间。没有指派人写“未指派”。
- “属于”指向所属的 Spec 或 Map，点它打开那个 Map View。没有上级时不画。
- 小节的顺序固定：描述、验收条件、被阻塞、执行记录。没有阻塞者时不画“被阻塞”；没有执行记录时写“还没有 Session 执行过这个 Task。”。正文怎么拆成描述和验收条件，照 `pane-layout.md`。
- “被阻塞”一行一个阻塞者：它自己的状态图形、编号、标题。点它钻进那个 Task。
- 返回栏里的动作和这个 Task 在列表那一行里的相同（`#detail-bar`）。没有动作的 Task 那里空着，不放停用的按钮。
- Pending Closeout 的 Spec：状态那一行照它作为 Task 的状态写（Pending Closeout 不是 Task Status），返回栏里是金色的“收尾核对”，和它那一行的一样。
- 执行记录一条一个 Session（`#detail-log`）：Session 的标识、时间、回报的结果。另一个宿主的 Session 前面写宿主名。有 Acceptance Evidence 时，用绿色的 ✓ 写在回报它的那一条里，连同出处。Deck 不判断验收是否通过。

## 地图

对应 #71、#78。整屏见 `#map`。

顶上一张档案卡说这是哪个 Spec 或 Map、进度多少，下面是 Child Task 的成就墙，一张卡片一个 Child Task。

- **档案卡**从上到下：种类和编号、标题、一句目标（Spec 正文的第一句，没有就省略）、四个计数、解锁进度。进度的数字是这一屏里最大的字。
- **成就墙的顺序**固定：可执行、进行中（本 Session、其他 Session、Orphaned）、阻塞、已解锁。阻塞那一段里，阻塞者排在被它阻塞的前面。
- **卡片**四行，高度一致：图形、编号和状态词；标题，最多两行；一行关系；脚注。脚注左边是时间（开着的写“更新”，已解锁的写关闭时间），右边是和列表里相同的那个动作。Orphaned 的卡片只放“接管”，“释放”在详情里。
- **Blocking Edge 写在关系那一行**：被阻塞的写 `被 #72 阻塞`，阻塞者写全，这个 Spec 或 Map 之外的阻塞者也写；挡着别人的写 `挡着 #73 #79`。两样都没有时，被其他 Session 占用的写它的 Session，Orphaned 写“Session 已结束”，已解锁的写有没有验收证据，其余留空。
- 被阻塞的卡片没有底色，标题变淡；已解锁的卡片沉下去，图形、编号和“已解锁”是金色。
- 被阻塞的卡片先画三张，其余收进墙下面的“还有 4 个被阻塞”。它是个按钮，点它全部画出。
- 点一张卡片进它的详情，来路是 `地图 / #64 / #76`。
- **切换**（`#map-switch`）。项目里不止一个 Spec 或 Map 时，档案卡右上角有“切换”。点它，内容换成 Spec 和 Map 的列表，画法和“任务”里它们的行一样，没有动作按钮；点一行选中并回到 Map View，“返回”不选直接回去。从“任务”里点 Spec 或 Map 那一行的“地图”也到这里。
- **Pending Closeout**（`#map-closeout`）。档案卡换成金色虚线框，编号旁写“待收尾核对”，进度条整条金色，脚注写“Child Task 已全部解锁，Spec 还没关闭。”，右边是金色的“收尾核对”。
- **没有 Spec 也没有 Map**（`#map-empty`）：“还没有 Spec 或 Map。带 Child Task 的 Task 会出现在这里。”

## 宿主给页面的

#68 在真实的桌面应用（26.1117.41037）里，从标签页中的页面读到的。页面只用到下面写明的几样。

- **握手结果**的 `hostContext` 里有 `theme`（`light` 或 `dark`）、`displayMode`（`fullscreen`）、`containerDimensions`（那次是宽 638、高 1034）、`locale`、`timeZone` 和 `styles.variables`（76 个颜色和字体变量）。页面只读 `theme`，见“整体”的深色和浅色；宽度跟着标签页走，不读 `containerDimensions`。
- **宿主声明的能力**有 `openLinks`、`message`、`serverTools`、`serverResources`、`updateModelContext`、`downloadFile`。页面用到三样：`ui/open-link`（“在 GitHub 打开”）、`ui/message`（预填，只放进输入框不发送）、`tools/call`（读取和各个动作）。
- **页面收到的通知**有 `ui/notifications/tool-input`、`ui/notifications/tool-result` 和 `ui/notifications/host-context-changed`。切换外观时 `host-context-changed` 带的是 `theme` 和 `styles.variables`，页面跟着换深浅；`adr6-thread-tab` 探针见过它只带容器尺寸。回合开始和结束时没有通知，所以 Pane 看不到 Session 忙不忙。
- **宿主缓存页面**：同一次运行里新开的 Matt Deck 标签页拿到的仍是应用启动后第一次读到的页面，改了 `plugin/codex/pane.html` 要重启桌面应用才看得到。

# 不设常驻服务，跨会话状态存本机文件

Deck 没有守护进程。每个宿主按需启动同一个 MCP 服务进程，agent 的工具调用和面板的读写都只经过它。占用、推荐记录、执行记录存在用户目录下的一个 SQLite 文件里，多个进程通过这个文件共享状态；任务本身仍然只存在于任务来源。

## Considered Options

- **常驻本地服务，面板和 agent 都连接它**（需求阶段的设想）：被否决。个人本地使用不值得多一个需要启动和保活的进程。
- **把占用写进 GitHub（assignee 或标签）**：被否决。会话级的占用和“失联”是本机概念，写进 issue 会让任务来源里出现只对这台机器有意义的状态。

## Consequences

- 占用状态换一台机器看不到。
- `/wayfinder` 会用 assignee 认领地图的子任务，那是任务来源里的事实。Deck 的占用是另一回事，Deck 不写入 assignee。
- Codex 如果最终走“独立窗口”退路（见 ADR-0006），需要按需启动一个本地页面服务，但它不保存状态。

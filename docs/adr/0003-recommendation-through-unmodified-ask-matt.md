# 推荐请求走未改动的 `/ask-matt`，结果由工具回报

“我现在该做什么”按钮在目标会话里以用户身份运行 `/ask-matt`，把任务快照作为参数附上，并要求 agent 调用 `deck_recommend` 工具回报结构化的推荐。技能文件不改，因为用户本机的 Matt skills 带有自己的定制，面板展示的和 agent 实际执行的必须是同一份。结果不从回答文本里解析，因为有的宿主根本读不到回答。

## Considered Options

- **另写一个 Deck 专用的推荐技能**：被否决。它会和用户自己的 `/ask-matt` 分叉。
- **另开一个后台会话来回答**：被否决。它不了解当前会话刚才的讨论，还多一次模型调用。
- **解析回答文本**：被否决。Codex 桌面应用的事件流外部进程收不到，文本格式也不稳定。

## Consequences

- `/ask-matt` 标了 `disable-model-invocation`，只能以用户输入的方式触发，不能让模型自己去调用。
- 会话忙碌时，请求由面板自己持有，空闲后再提交，而不是交给宿主排队。宿主排队的请求无法撤回，而且按钮的处理函数等待它返回会超出 Claude Code 的 10 秒预算（2026-11-11 原型实测）。
- agent 没有调用工具时，只有 Claude Code 能退回显示回答原文。

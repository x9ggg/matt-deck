# 面板按宿主各写一份，只共享内核

每个宿主用它自己的原生面板机制，界面代码不跨宿主复用，共享的只有任务内核。Claude Code 侧用 Mods 面板：它运行在会话内部，天然知道自己属于哪个会话，能感知会话是否忙碌，能以用户身份运行 `/ask-matt`，也能拿到回合的结果。这些是外置的网页面板拿不到的。代价是界面要写多份，而且 Mods 面板不是网页，只能用引擎自带的元素绘制。

## Considered Options

- **同一套 Web 前端嵌进所有宿主**（需求阶段的最初设想，参考项目也是 React 网页）：被否决。Claude Code 终端没有可以嵌网页的位置，网页也无法得知当前会话或向它提交提示词。

## Consequences

- 在 Claude Code 终端里，面板只有在全屏且不少于 110 列时才停靠在侧边，否则显示在输入框上方；未经用户操作的自动打开同样需要不少于 110 列（2026-11-12 在 2.1.322 上实测：130 列自动停在侧边，100 列不自动出现，见 #4）。
- 2026-11-11 用一次性原型在 Claude Code 2.1.322 上验证了会话识别、忙碌感知、按钮触发 `/ask-matt` 和结果回传。重启、`/clear`、恢复会话之后的面板状态在 2026-11-12 核对过，结论在 #4 的评论里：项目里有允许 Deck 服务工具的权限规则时（没有时面板起不来，#23），重启和恢复会话之后面板自动出现，`/clear` 之后面板停在读取中（#24）。原型保存在 `prototype/claude-code-mods-probe` 分支。
